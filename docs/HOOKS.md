# 插口：两类，不是四个

> 群友的分法比「四个钩子」更准：
> **功能接口**（可加性，越多越好）vs **装配接口**（顺序敏感，越少越好）。
> 登记表见 [HOOKS-TABLE](./HOOKS-TABLE.md)。

## 一、分类标准

| 类别 | 判据 | 例子 | 数量策略 |
| --- | --- | --- | --- |
| **功能接口** | 别人挂进来、**不改主流程** | 观察者（收消息/发完）、HTTP 路由、MCP 工具 | 越多越好（但要算上下文成本） |
| **装配接口** | 插在主流程**中间动手脚** | 提示词内容块、唤醒闸门、生成后改写 | 越少越好（顺序/缓存/责任） |

分界线一句话：**能不能交换顺序而不改变结果**。

## 二、我们现在的插口

### 装配接口（顺序敏感）

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| 内容块（content） | **10** | 人格 / 管理员 / B站简报 / 记忆卡 / 会话记忆 / 印象 / 欠事 / 自记 / 心情 / 恢复提示 |
| 拦截器（interceptor） | **1** | `chat-control`（静音 / 学习模式） |
| 生成后改写 | **0** | 预留 |

内容块虽然 10 个，但它们**只追加、不互相改写**——真正的「能否决主流程」的装配接口只有 **1 个**。
`verify.mjs` 会检查：**拦截器 ≤ 3**。

### 功能接口（可加性）

| 类型 | 数量 |
| --- | --- |
| 观察者（observer） | 1（`recent-chat`） |
| HTTP 路由 | 194 |
| MCP 工具 | 49 |

观察者几乎零成本；路由要过鉴权；**工具定义会进提示词，是最贵的一类**——49 个工具是后续要盘的账。

## 三、登记表（关键）

光「少」不够，还要有表。`docs/HOOKS-TABLE.md` 自动生成：

```bash
node scripts/hooks-table.mjs --write
```

每行记四件事：**谁注册的、只读还是能改、影不影响缓存、什么时候该复查**。

`verify.mjs` 会校验：表必须覆盖所有内容块，缺一个就报错。

## 四、新增一个块（不碰 bridge.js）

```js
registerPromptBlock('weather', () => weatherBlock(), {
  order: 55,
  readOnly: true,
  affectsCache: true,     // 读了文件就必须标，否则缓存会脏
  owner: '天气',
  reviewWhen: '改天气接口时',
});
```

然后跑 `node scripts/hooks-table.mjs --write` 更新登记表，再跑 `node scripts/verify.mjs`。

## 五、失败隔离

`src/hooks.js` 里每个调用都包 try/catch：单个块抛异常只记 `[hooks:*] 失败`，不影响其它块与主流程。

## 六、不搬的东西（保命层）

限流、审计、去重、日志脱敏、错误只报主人——**不进插口**，留在主干：

- 它们必须对**每一次**发送生效，走插口可能被漏注册；
- 出错要立刻可见，藏在模块里会变难查。
